## v0.1.0 (2026-10-15)

### Changed

- An unknown step in a needs list, or a setup. entry in a setup step fails with the step's file position and a config: prefix.
- The rerun_step MCP tool reports a step that ran and failed as a result with its status and logs, not as a tool error. It also reports the steps whose message changed, as well as those whose state did.
- Plugin loading and port forwarding errors are prefixed load: and portforward: instead of supervisor:.
- Plugin authors: plugin.Env.EngineConfig is removed. It was always empty, so read plugin.Env.Engine alone to learn which container engine is in use.
- Plugin authors: Route and ExposedPort take a plugin.Upstream (an address or a relay target) instead of a socks5:// string, ExposedPort.Protocol is a plugin.Protocol, and Env.Engine, Env.Scope and StepContainers.Scope are typed, and StepContainers.Step no longer carries a setup. prefix. The plugin wire protocol changes with them, so rebuild plugins against this release.
- Plugin authors: kevin sends a plugin its with block with the defaults of its CUE schema filled in, for every field the schema declares without a ?. The block is also checked against the schema on every call, and a field declared without ? that has no default and no value is an error. Wrap a step in plugin.Typed to receive the block as a Go struct. plugin.Handshake, plugin.GRPCPlugin, plugin.Name and plugin.ProtocolVersion are removed from the SDK.
- A plugin config: block receives the defaults its schema declares, as a step with block does.

### Fixed

- A group that re-exports a sensitive member output keeps it marked sensitive, so it is redacted like any other sensitive output.
- The proxy renews a host's certificate halfway through its 7-day lifetime, so a run longer than a week no longer serves expired certificates.
- kevin do resolves a setup group that a command's step needs. kevin do gives plugins the same environment fields (CA path, domain, project directory, scope) as kevin run. kevin teardown gets them too.
- kevin do rejects an unknown --engine, as run and teardown do.
- KEVIN_PROJECT_STATE_DIR moves the environment's workspace, logs, run files, and extracted plugins, not just the CA files. The package cache, plugin index, and trust stores follow KEVIN_USER_STATE_DIR.
- A plugin receives the scope of the step it acts on, including when kevin run or kevin do exports a step of the other scope.
- A rerun replaces the proxy routes and egress hosts of its step, and a step that fails to come up or is removed leaves none behind.
- A rerun, a failure or a removal releases the relay DNS names and extra listeners of an intercept route that the step no longer names.
